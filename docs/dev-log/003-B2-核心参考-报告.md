## 三 · 核心机制

TS 的结构类型是本批最主要的对手。母本里 Java 免费提供的名义类型，在 TS 里要靠三种手段补：

1. 标识符用品牌类型，唯一允许 `as` 转成品牌的地方是各自的构造函数。
2. 值对象和聚合的状态放 `#private` 字段，类才变成名义类型。
3. 进程外的数据先经 schema 解析，再经领域工厂变成领域类型，禁止直接断言类型。

## 四 · 安全防线

本批是文档；与安全相关的规则：边界一律 schema 解析、禁止断言未解析输入（typescript-modeling「Boundary Validation」）；错误对外只给稳定代码与安全消息、内部细节只进日志（error-handling「Rules」）。

## 六 · 我替你定的 13 个决定

1. **重建聚合不重跑创建时的策略**：`reconstitute` 不检查"必须在未来开始"这类创建时策略，只靠值对象工厂拒绝结构上不可能的数据（如结束早于开始）。理由：已存数据会随时间或策略变化而合法地不满足创建规则。放弃了"重建时全量校验"。（B1 遗留项）
2. **时间点用品牌化的 `EpochMillis`**：领域内不用 `Date`（可变、带本地时区 API），也不用 `Temporal`（运行时支持未核实）。日历与时区只在边界转换。
3. **用字符串字面量联合，不用 `enum`**。
4. **值对象状态必须放 `#private`**：实测发现只用 `readonly` 公开字段时，对象字面量能冒充值对象并绕过工厂校验。
5. **标识符用品牌原始类型，不用类**；只有构造函数里允许 `as` 转品牌，其他地方出现即为审查问题。
6. **错误按 `code` 匹配**，不只靠 `instanceof`（同一个包在进程里有两份时会出现两个类）。
7. **抛还是返回的判据**："正确的调用方在正常使用中能不能触发它"。能，且调用方要据此反应，就返回 Result；不能，就抛出。
8. **每个上下文只有一个公开入口 `index.ts`**，上下文内部禁止 barrel 文件。
9. **类型检查先用一个根 tsconfig**，整库检查变慢时才上 project references。
10. **包的 `exports` 直接指向 TS 源码**，不为每个包单独构建。
11. **共享内核零运行时依赖，不放 `AggregateRoot` 基类**：偏好类型、接口与函数。母本把 `AggregateRoot`、`Entity` 基类列为好候选，这里没有列入。
12. **乐观并发**：聚合快照带 `version`，由仓储检查并递增。
13. **"同一会议室时段不重叠"这类集合约束必须写明守法**：二选一——由一个聚合持有集合（如按会议室和日期的 `RoomSchedule`），或数据库约束加翻译后的失败。具体选哪个留给 B4 示例工程。

## 九 · 复核更正（2026-11-03，发起人要求复核此前推荐）

1. **`private` 关键字的说法写错了，已改正文**。typescript-modeling 原写"类只有声明 `#private` 字段才是名义类型""`private` 关键字编译后消失、保持结构兼容"。tsc 7.0.2 实测：两个都带 `private` 关键字成员的类互相不可赋值，对象字面量也不能冒充，`private` 关键字同样让类在编译期成为名义类型。选 `#private` 的真实理由只剩运行时私有：`private` 关键字字段仍可经方括号访问、类型断言或普通 JS 读写，且会被 `JSON.stringify` 输出。已改第 44、96、208 行附近三处。决定 4（值对象状态放 `#private`）结论不变，理由改为运行时私有。
2. **"领域只用语言标准库"边界不清，待裁决**：B1 裁决 3 只点名了 `node:*` 与 `bun:*`；`fetch`、`crypto`、`setTimeout`、`performance` 这类不在 `node:` 下的平台全局对象同样是 I/O、随机性或时间，规则应写明它们也只进基础设施层，只允许 ECMAScript 内置对象（如 `Math`、`Array`、`Map`、`JSON`、`Intl`）。
3. **层名 `interface`** 与 TS 关键字 `interface` 同名，文中说"interface 层"时容易与"接口类型"混淆。待裁决是否改为 `interfaces`（与 Java 版一致）。
