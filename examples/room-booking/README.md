# Example: Room Booking

A runnable modular monolith that exercises every rule of the `typescript-domain-driven-design` skill.

- `packages/shared-kernel`: `Brand`, `Result`, `DomainError`, `EpochMillis`, shared identifiers, `Clock`, `IdGenerator`
- `packages/contracts`: published language (zod schemas): integration events, the room view
- `packages/room-catalog`: rooms and their lifecycle; exposes a facade
- `packages/booking`: bookings with time-slot conflicts, row-level authorization, optimistic locking, an outbox, an ACL to room-catalog, Hono routes
- `packages/app`: composition root, demo authentication, configuration, server entry

Migrations are generated by drizzle-kit and compiled into the program (`packages/sqlite-support`), because a single-file binary has no `drizzle/` folder at runtime.

Tested with Bun 1.3.12, TypeScript 6.0.3, drizzle-kit 0.31.11, Hono 4.13.16, Drizzle 0.45.4, zod 4.6.7, dependency-cruiser 18.7.2, ESLint 10.14.0, typescript-eslint 8.72.1.

```bash
bun install
bun run check      # tsc + dependency-cruiser + eslint + bun test
NAME=add-x bun run db:generate   # after a schema change: drizzle-kit generate per context, then embed
bun run build      # single-file binary in dist/
PORT=3000 DB_PATH=room-booking.db ./dist/room-booking
```

The authentication middleware trusts `x-member-id` and `x-member-role` headers. It exists only to make the example runnable; replace it before any real use.
